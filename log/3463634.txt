★ Insight ─────────────────────────────────────

  FWStack vs Markdown TODO — Temel Fark:

  ┌───────────────┬───────────────────────────────────┬────────────────────────────────────────────────────────────────┐
  │    Özellik    │           Markdown TODO           │                            FWStack                             │
  ├───────────────┼───────────────────────────────────┼────────────────────────────────────────────────────────────────┤
  │ Validation    │ Yok — yazılan planı AI "anlamalı" │ Compiler validates — görevler acceptance criteria ile tanımlı  │
  ├───────────────┼───────────────────────────────────┼────────────────────────────────────────────────────────────────┤
  │ Execution     │ Manuel — AI'ya "şunu yap" dersin  │ Deterministic — gerçek araçlar çalışır (git, npm test, eslint) │
  ├───────────────┼───────────────────────────────────┼────────────────────────────────────────────────────────────────┤
  │ Repeatability │ Her seferinde baştan              │ Workflow'lar derlenmiş, tekrar kullanılabilir                  │
  ├───────────────┼───────────────────────────────────┼────────────────────────────────────────────────────────────────┤
  │ Quality Gates │ Yok — AI kendi karar verir        │ Var — test geçmeden devam edemez                               │
  └───────────────┴───────────────────────────────────┴────────────────────────────────────────────────────────────────┘

  Örnek Senaryo:

  # Markdown Approach
  - [ ] Auth middleware ekle
  - [ ] Test yaz
  - [ ] Review iste
  → AI "tamamlandı" der ama test patlamış olabilir, gözden kaçar.

  // FWStack plan.ts workflow
  // 1. Context topla (deterministic)
  // 2. AI plan üret (waitForAgent pause)
  // 3. Validate — her görev için:
  //    - acceptance.checks: ["npx tsc --noEmit", "npx vitest run"]
  // 4. Implement mode — her görevi AI yapar, test otomatik koşar
  // 5. Gate — test geçmezse devam etmez

  ─────────────────────────────────────────────────

  FWStack daha iyi zaman:

  - Kod review — lint + diff → AI analiz → sıralı rapor
  - TDD — AI test yazar (RED) → koşar → AI implemente eder (GREEN)
  - Security audit — SAST çalıştır → OWASP analizi → confidence gate
  - Ship — test geçmeden asla release'e izin vermez

  Markdown daha iyi zaman:

  - İlk kez keşif (discovery) aşaması
  - Basit not alma
  - Hızlı brainstorming

  Senin için hangi senaryolar önemli? Kod kalitesi/TDD disiplini mi, yoksa hızlı planlama mı?

  2. Tüm Tool'ların Kullanımı

  🔍 browse - Community Workflow'ları Listele

  /fwstack:browse
  /fwstack:browse <query>
  Ne yapar: Registry'den topluluk workflow'larını arar ve listeler

  🔍 review - Kod İncelemesi

  /fwstack:review
  /fwstack:review --project /path/to/project
  Ne yapar:
  1. git diff + eslint/tsc çalıştırır (parallel)
  2. AI analiz yapar (waitForAgent)
  3. Bulguları severity'ye göre sıralar
  4. Markdown rapor üretir

  📋 plan - Plan Oluşturma

  /fwstack:plan <feature açıklaması>
  /fwstack:plan "Add auth middleware" --mode implement
  Ne yapar:
  1. Proje context'ini toplar (file tree, deps, commits)
  2. AI plan üretir (her görev acceptance criteria ile)
  3. Validator kontrol eder (TBD, "as needed" reddeder)
  4. Implement mode: Her görevi tek tek yapar ve test eder

  🔄 tdd - Test Driven Development

  /fwstack:tdd <task description>
  Ne yapar:
  1. AI test yazar (agent pause)
  2. Test çalıştırır, assert RED (exit != 0)
  3. AI implemente eder (agent pause)
  4. Test çalıştırır, assert GREEN (exit == 0)
  5. Geçemezse devam edemez (hard gate)

  🔐 security - Güvenlik Denetimi

  /fwstack:security
  Ne yapar:
  1. npm audit + semgrep çalıştırır (parallel)
  2. AI OWASP + STRIDE analizi yapar
  3. Confidence < 8 olanları düşürür
  4. Severity'ye göre sıralar

  📦 ship - Release Pipeline

  /fwstack:ship
  Ne yapar:
  1. Feature branch kontrolü
  2. Test hard gate (test geçmezse durur)
  3. Changelog oluşturur (agent pause)
  4. Version bump önerir

  📥 install - Workflow Yükleme

  /fwstack:install <workflow-name>
  /fwstack:install workflows/moraispgsi--depAudit
  Ne yapar:
  1. Registry'den workflow indirir
  2. .fwstack/workflows/ altına kurar
  3. Bağımlılıkları auto-install eder
  4. Bir sonraki tool call'da auto-discover olur

  ▶️ run - Özel Workflow Çalıştırma

  /fwstack:run /path/to/workflow.ts
  Ne yapar:
  1. Herhangi bir .ts workflow dosyasını çalıştırır
  2. Agent pause'ları sen yönetirsin
  3. Auto-discovery yoktur, direkt çalışır

  ➕ create - Workflow Oluşturma (Test edilmedi)

  /fwstack:create "Describe what you want"
  Ne yapar:
  1. Doğal dil açıklamasını alır
  2. AI spec üretir (validator kontrolü)
  3. Workflow dosyasını yazar
  4. fw validate ile doğrular
  5. .fwstack/workflows/ altına kurar

  🔄 migrate - Markdown → Workflow (Test edilmedi)

  /fwstack:migrate /path/to/skill.md
  Ne yapar:
  1. Markdown skill dosyasını parse eder
  2. Format tipini algılar (Claude Code, gstack, freeform)
  3. Adımları sınıflandırır (deterministic/agent/gate)
  4. Plan oluşturur, onay ister
  5. Workflow dosyasına çevirir

  🚀 publish - Workflow Yayınlama (Test edilmedi)

  /fwstack:publish /path/to/workflow.ts
  Ne yapar:
  1. Workflow'u validate eder
  2. Metadata onayı ister
  3. GitHub PR açar (gh CLI ile)
  4. fwstack-community registry'sine gönderir
